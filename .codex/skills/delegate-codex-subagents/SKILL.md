# 子 Agent 委派

仅在并行收益明显高于协调成本时使用。优先遵循用户对是否委派、模型和并行度的明确要求。

## 拆分与派发

- 每个子任务只包含一个可独立验收的目标。
- 并行任务不得修改相同文件；有依赖的任务分批执行。
- 优先按 Plugin、Kit、Framework 等功能边界拆分，不为凑并发制造碎片任务。
- 使用当前环境提供的内置子 Agent 工具，不启动外部代理进程或创建中间任务文件。

任务说明应简洁、自包含，并写明：

- 目标和必要上下文；
- 允许修改的文件或窄目录；
- 验收方法和停止条件；
- 禁止事项与交付格式。

只传递完成任务所需的信息，不附带无关历史、敏感信息或凭据。

## 编排与验收

主 Agent 负责拆分、调度和最终验收，也可以处理未委派的工作或在委派失败后接管。子 Agent 运行期间，主 Agent 可继续处理互不重叠的任务。

子 Agent 报告完成后，主 Agent 应：

1. 检查实际变更是否处于允许范围；
2. 独立运行与风险相称的验证；
3. 确认并行任务的接口、命名和行为一致；
4. 确认用户已有修改未被覆盖或意外纳入。

结果不完整时，优先向原 Agent 补充具体要求；无法继续时再重新委派或由主 Agent 接管。

## 安全边界

委派不扩大用户授权。未经明确许可，不得让子 Agent 执行发布、部署、合并、推送、凭据操作、权限扩大、外部消息或不可逆操作。
