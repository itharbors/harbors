# 内置 Luna Subagent 并行委派

## 工具与固定配置

只使用 `multi_agent_v1` 提供的以下工具：

- `spawn_agent`：创建子代理。
- `send_input`：向运行中的子代理补充信息、修正方向或请求继续处理。
- `wait_agent`：等待子代理完成或需要关注的状态。
- `close_agent`：完成审查后关闭子代理。

每次调用 `spawn_agent` 都必须固定使用：

```text
model = "gpt-5.6-luna"
reasoning_effort = "high"
```

默认最多同时保持 4 个活跃子代理。只有在已有代理结束、失败并被关闭，或任务被重新安排后，才补充新的活跃代理。

不得启动外部代理命令，不创建任务描述文件，不调用旧的 Python 启动器，不依赖外部 Relay 配置或操作系统级隔离包装。每个子代理的任务说明必须作为自包含的内联 prompt 传给 `spawn_agent`。

## 主 Agent 的职责边界

主 Agent 是编排者和验收者：

1. 理解目标并画出子任务依赖关系。
2. 把工作拆成边界明确、可独立验收的原子任务。
3. 以互斥的写入范围派发任务，并在 prompt 中写清上下文、目标、允许修改、验收命令和禁止事项。
4. 子代理运行期间只做状态编排、只读检查和必要的验收准备，不重复实现子代理负责的代码、测试或文档。
5. 子代理完成后检查实际变更，独立运行验收命令，确认接口和行为一致，再决定是否通过。
6. 完成实际变更审查和验收后，对对应子代理调用 `close_agent`。

以下动作不得由委派流程自动执行：发布、部署、合并、推送、凭据操作、权限扩大、外部消息和不可逆动作。除非用户明确授权，否则不要把这些动作交给子代理。

## 原子拆分规则

每个子任务必须满足：

- 只有一个可验证目标。
- 所需上下文可以完整写入内联 prompt。
- 写入范围是精确文件或窄目录，并且不与同批其他任务重叠。
- prompt 明确验收命令和禁止事项。
- 不依赖同批其他任务尚未产生的结果；有依赖的任务放到后续批次。

优先按功能单元拆分。Plugin、Kit 和 Framework 应分别作为边界；跨边界需求拆成互不重叠的任务，并在主 Agent 侧汇总验收。不要为了凑并发拆出无法独立验收的碎片。

## 内联 prompt 要求

每个 `spawn_agent` prompt 至少包含以下内容：

```text
任务目标：一个明确且可验收的结果。
上下文：完成任务所需的最小事实、路径和既有约束。
允许修改：精确文件或窄目录。
验收检查：主 Agent 可以独立复核的命令或检查。
禁止事项：不得触碰的文件、行为或外部动作。
交付格式：说明实际改动、验证结果和任何阻塞。
```

prompt 只提供完成当前任务所需的信息，不复制完整对话，不要求子代理读取、输出或修改凭据。

## 并行执行流程

1. 先完成拆分，标注每个任务的写入范围和依赖。
2. 对没有依赖且写入范围互斥的任务，使用 `spawn_agent` 并行创建，最多 4 个活跃代理；每次都带固定的 Luna High 配置。
3. 通过返回的代理标识跟踪任务，不创建外部协议文件。
4. `wait_agent` 要克制使用：优先等待一个需要完成或需要处理的代理，避免无意义地频繁轮询；只在状态变化、阶段衔接或验收需要时等待。
5. 代理失败或方向不完整时，优先使用 `send_input` 提供具体修正；若无法继续，关闭原代理后重新 `spawn_agent`，并缩小任务范围或补充缺失上下文。
6. 子代理报告完成不等于通过。主 Agent 必须独立检查实际差异、边界和验收命令结果。
7. 验收通过后调用 `close_agent`，再安排依赖它的后续任务。

## 只读验收清单

对每个子任务至少检查：

1. 实际变更全部位于 prompt 声明的允许范围内。
2. 独立运行 prompt 中的验收命令，不把子代理自报结果作为唯一证据。
3. 并行任务之间的接口、命名和行为一致。
4. 用户已有改动未被覆盖、还原或意外纳入。
5. 失败项已经通过 `send_input` 修正，或重新委派后再次独立验收。

主 Agent 可以运行只读 Git 检查、测试和构建命令；不得借此替代子代理实现任务。只有所有任务都通过独立验收后，才能汇总交付，并报告派发范围、实际验证和残余风险。
