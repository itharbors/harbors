# Agent Guard 监控界面重排设计

## 目标

将 Agent Guard 从纵向堆叠的单页改为以任务为中心的双 Tab 界面，让用户先查看实时与历史流量，再按需进入事件预警，同时让页面完整适配 Web 与 Electron 宿主提供的可用窗口。

## 信息架构

顶部固定保留产品标题、说明和保护状态，并在其下提供两个符合 ARIA Tabs 语义的导航项：

- **流量概览**：依次展示观测路由、历史用量和本地历史管理。
- **事件预警**：展示事件记录、异常处理操作和预警策略；Tab 显示当前事件数量。

默认打开流量概览。用户切换 Tab 后，2 秒实时轮询与 30 秒历史轮询不得重置当前 Tab、键盘焦点、策略表单输入、滚动位置或历史筛选状态。

## 布局与响应式

根节点和工作区占满宿主提供的宽度，并至少填满可用视口高度。内容不再限制为固定画布，观测路由和历史用量采用上下排列。

- 宽屏：路由数据充分利用横向空间，历史摘要卡保持紧凑网格。
- 中等宽度：路由指标换到下一行，摘要卡降为两到三列。
- 320–640 px：标题、Tab、控制器和摘要卡依次转为单列或可换行布局，不产生页面级横向滚动。

延续现有深海蓝监控台视觉语言和等宽数据字体，不引入新的装饰体系。以顶部 Tab 的活动指示线作为唯一新增的强视觉标识。

## 历史用量

保留“网络流量 / 模型用量”和时间范围切换，删除 Claude/Codex 过滤按钮。查询始终包含 Claude、Codex 和未来可识别的全部智能体来源，由历史聚合层按时间桶合并。

折线图始终表达指标而不是智能体：

- 网络流量：上行、下行两条线。
- 模型用量：输入 Token、输出 Token 两条线。

同一指标在相同时间桶内累加所有来源。只有存在采集值的来源参与求和；若整个时间桶均无数据，则保持缺失并绘制断线，不转换为零。图表提供可见图例和可访问文本，颜色之外再用实线/虚线区分。

网络摘要显示上行、下行及覆盖率。模型摘要采用与观测路由一致的两排数据卡：第一排为输入 Token、输出 Token、缓存 Token，第二排为请求数、会话数；每项继续显示覆盖状态。摘要总值必须与图表所用聚合数据一致。

## 事件预警

事件页沿用现有事件状态、恢复、结束和忽略操作。事件列表是主内容，策略配置作为同一 Tab 内的次级区域；宽屏可并排，窄屏上下排列。无事件时明确说明监控仍在运行。

## 渲染与状态

将稳定的页面外壳和导航状态与轮询数据分离。轮询更新不得无条件重建用户正在操作的整棵 DOM；至少应保存并恢复活动 Tab、焦点、滚动位置和未提交表单值。异步历史请求继续使用版本号丢弃过期响应。

数据接口保持兼容，不修改采集、策略和事件命令协议。前端删除智能体筛选交互后，查询传递完整来源集合；聚合层负责跨来源合并，避免在视图层重复实现数据语义。

## 错误与空状态

- 实时数据不可用时显示已有错误详情和重试入口。
- 历史数据加载、空数据和请求失败保持独立状态，不影响实时路由。
- 某一历史指标缺失时保留图表断点，并展示覆盖提示。
- 事件为空时显示正常空状态；事件操作失败时保留当前 Tab 并展示错误。

## 验收标准

1. 顶部 Tab 支持鼠标、键盘方向键、Enter/Space 和正确的 ARIA 关联；事件数徽标准确。
2. 轮询期间当前 Tab、焦点、滚动位置、策略表单输入和历史选择不丢失。
3. 320 px 至宿主全宽没有页面级横向滚动，工作区至少占满可用窗口。
4. 历史区不再出现 Claude/Codex 过滤器；网络图只有上行/下行，模型图只有输入/输出 Token。
5. 每个时间桶的曲线值等于全部来源之和；全缺失桶显示断点而不是零。
6. 模型摘要以两排展示五个指标，数值、覆盖率和趋势数据一致。
7. 事件与策略仅显示在事件预警 Tab，所有现有操作仍可用。
8. Agent Guard 单元测试、可访问性测试和官方 `kit:check` 全部通过，并在 `npm run dev:web` 页面完成验收。

## 非目标

- 不调整采集器、阈值算法或事件判定规则。
- 不新增第三方图表库。
- 不为本次改造启动或依赖 Electron；桌面专属能力不在范围内。
