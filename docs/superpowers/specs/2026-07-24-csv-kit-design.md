# CSV Kit 设计

## 背景与目标

Harbors 已有 SQLite Kit，但查看 CSV 仍需要先导入数据库或离开 Harbors。CSV Kit 提供一个与 SQLite
Kit 视觉和交互一致的中文只读工作台：用户选择本地 CSV/TSV 文件后，可以确认解析参数、分页浏览、
搜索、筛选、排序、查看完整单元格和导出当前结果。

首版把“读取工具”解释为只读数据检查器。它不会修改源文件，也不提供记录增删改、公式、图表、跨文件
关联或 SQL 工作区。只读边界既符合原始需求，也避免 CSV 回写时对换行、编码、引号和原始格式造成不可逆
变化。后续若需要编辑，将以“另存为”工作流单独设计。

## 用户工作流

1. 用户从顶部连接栏选择 `.csv`、`.tsv` 或 `.txt` 文件。
2. Kit 读取文件样本，自动建议 UTF-8/GB18030 编码、逗号/制表符/分号分隔符和首行表头；用户可以在
   打开前覆盖建议。
3. Core 流式解析源文件并建立会话级临时索引。连接栏展示处理进度；索引完成后才启用全量搜索、筛选、
   排序和导出，避免展示不完整结果。
4. 左侧资源面板展示文件名、大小、行列数、解析配置和字段列表。
5. 数据页默认每页 50 行，支持 25、50、100 或 250 行分页；用户可以执行全字段快速搜索、单字段筛选、
   单字段升降序排序，并双击查看完整单元格。
6. 结构页展示字段序号、显示名称、内部唯一 ID，以及空值、最大长度等只读统计。
7. 用户可将当前搜索、筛选和排序结果导出为 UTF-8 BOM CSV；导出总是写入新文件，不覆盖源文件。
8. 切换文件、关闭文件、卸载插件或结束 Session 时，Kit 关闭文件句柄并删除本 Session 的临时索引。

## 架构与组件

新增 `kits/csv`，沿用 SQLite Kit 的顶部连接栏、左侧资源面板和右侧标签工作区布局，但只保留与 CSV
相关的三个插件：

### `@itharbors/csv-core`

无 Panel。它是唯一允许访问源文件和临时目录的插件，负责：

- 校验并以只读方式打开本地文件；
- 样本读取、编码与分隔符建议；
- 使用成熟 CSV 解析器处理引号、转义引号、字段内换行和 UTF-8 BOM；
- 流式建立临时行存储及查询索引；
- 执行分页、搜索、筛选、排序、统计和导出；
- 管理连接 revision、任务取消、文件句柄和临时资源清理。

索引只保存于操作系统临时目录，名称使用随机 session 标识，不与源文件同目录创建 sidecar。实现使用
Kit 已有的 `better-sqlite3` 原生能力作为内部临时索引：CSV 解析器逐批写入一张临时表，字段按原始文本
保存，并为稳定行号建立主键。该数据库只是不可见的查询实现细节；用户不会看到 SQLite 对象或 SQL
界面。这样既避免把全量数据发送到浏览器内存，也能以确定语义提供分页、过滤和排序。

### `@itharbors/csv-explorer`

贡献 `connection` 与 `explorer` 两个 Panel。`connection` 负责文件选择、解析建议、参数确认、打开进度、
取消、刷新和关闭。`explorer` 展示当前文件摘要和字段，字段选择通过广播同步到工作区。

文件刷新会重新采样和建索引，不静默沿用可能已经不适用的自动检测结果；用户显式选择的配置仍保留在
表单中，供其再次确认。

### `@itharbors/csv-data`

贡献 `data` 和 `schema` 两个 Panel。`data` 负责分页表格、搜索、筛选、排序、单元格详情和导出；
`schema` 负责字段与统计信息。Panel 只持有当前页和查询状态，通过 request 调用 Core，不直接访问文件
系统，也不导入其他插件实现。

共享的可序列化请求、响应、事件、错误 envelope 与类型守卫放入 `packages/csv-contracts`。该包不得导入
Node API、DOM、CSV 解析器或插件实现。

## 数据流与状态

```text
选择文件
  -> csv-core 只读采样
  -> csv-explorer 展示建议并确认参数
  -> csv-core 流式解码和解析
  -> 分批写入 Session 临时索引
  -> 广播连接/进度 revision
  -> csv-data 按页请求查询结果
```

每次打开、刷新、关闭或失败都会递增 `connectionRevision`。所有耗时请求携带 revision；Panel 丢弃旧
revision 的结果，Core 在切换文件时取消旧解析任务。连接快照区分 `closed`、`sampling`、`indexing`、
`ready` 和 `error`，避免用单个布尔值混淆可交互状态。

查询状态包含页码、页大小、快速搜索、零到多个字段筛选和一个排序字段。筛选操作首版支持 `contains`、
`equals`、`is-empty` 与 `is-not-empty`。CSV 值按原始文本处理；排序使用确定性的大小写不敏感文本顺序，
相同值再按源记录号排序。首版不推断数字或日期类型，避免前导零、超长整数和地区日期被错误改写。

表头字段使用稳定内部 ID `column-1`、`column-2` 等引用。显示名称保留源文本；空表头显示为
“未命名列 N”，重复表头追加仅用于界面的序号，但不修改原值。无表头模式生成“列 1”“列 2”等名称。
记录宽度不一致时，以全文件最大宽度建立列集合：缺失字段为空字符串，额外字段获得生成列名，并在连接
摘要中显示不规则记录数量。

## 解析、编码与资源边界

- 支持 UTF-8（含 BOM）和 GB18030。自动模式只在存在 BOM 时确定编码；无 BOM 时先严格尝试 UTF-8，
  失败后建议 GB18030，并始终允许用户覆盖。首版不宣称可靠识别任意编码。
- 自动分隔符只在逗号、制表符和分号中选择，依据样本记录的字段数一致性评分；分数相同优先逗号。
- 引号固定使用双引号，支持 RFC 4180 风格的双引号转义和字段内换行。行尾接受 LF 与 CRLF。
- 默认文件大小上限为 2 GiB，并在开始索引前校验。临时目录可用空间不足、字段数超过 10,000、单条
  记录解码后超过 16 MiB 或单字段解码后超过 16 MiB 时明确失败，防止失控的内存与磁盘使用。
- 解析采用批量事务写入，不在 Node 或浏览器中保留完整数据集。取消与失败会关闭句柄并清理未完成索引。
- 导出通过流式读取当前查询结果写入用户选择的新路径；目标已存在时拒绝覆盖。单次导出不设人为行数
  截断，但可取消并报告已写行数。

## 插件协议

Core 提供下列主要 request：

- `sampleFile(input)`：校验路径并返回文件摘要与解析建议；
- `openFile(input)`：按显式配置开始索引并返回新的连接快照；
- `getConnectionState()`：返回连接、进度、配置与 revision；
- `cancelOpen(input)`：取消匹配 revision 的索引任务；
- `closeFile()`：幂等关闭并清理当前会话资源；
- `getSchema(input)`：返回字段与不规则记录摘要；
- `getRows(input)`：返回确定性分页结果与总数；
- `getColumnStats(input)`：按需返回字段统计，避免打开文件时计算全部统计；
- `exportRows(input)`：导出当前查询并返回路径、行数和耗时；
- `cancelExport(input)`：取消匹配任务。

广播主题包括连接变化、索引进度、schema 就绪和导出进度。公开错误使用 `$csvError` envelope，至少包含
稳定错误码、中文信息以及可选的源记录号、物理行号和字段号。Panel 使用共享解包函数转换为可展示错误。

## 错误处理与安全

- 路径解析为绝对路径；打开时要求目标是普通文件，并拒绝目录、符号链接和超过上限的文件。
- 源文件始终使用只读句柄。打开和导出路径不能相同；导出目标已存在时必须让用户另选路径。
- 样本或解析失败时保留路径与用户配置，显示错误位置和修复建议，不自动切换配置后重试。
- 记录宽度不一致属于可恢复警告；未闭合引号、非法转义和无法解码的字节属于阻断错误。
- 新文件索引成功前保留旧的 ready 连接；新任务失败或取消时，旧文件仍可浏览。
- 插件 unload、Session dispose 和重复 close 都必须安全释放资源；进程异常遗留的随机临时目录在下次启动
  时按所有者标记和过期时间清理，不扫描或删除无关目录。

## 界面与可访问性

CSV Kit 复用 SQLite Kit 的中文工业风格、尺寸层级、状态栏和表格交互，使用户无需学习另一套工作台。
顶部连接栏在窄窗口换行；左侧面板最小宽度 220px；数据区允许双向滚动并保持表头可见。

所有输入都有可见标签；进度通过 `role="progressbar"` 提供数值；错误使用 `role="alert"`；状态变化使用
克制的 `aria-live`。表格行、分页、排序、筛选、标签页、对话框和取消操作均支持键盘。颜色不作为连接、
警告或排序状态的唯一表达方式。

## 测试与验收

Core 单元测试使用临时目录中的真实文件，覆盖：

- UTF-8/BOM/GB18030、三种分隔符、LF/CRLF、引号、转义引号和字段内换行；
- 有表头、无表头、空/重复表头、空文件、仅表头和不规则记录宽度；
- 打开进度、取消、切换成功、切换失败保留旧连接以及 close/unload 幂等；
- 分页、快速搜索、组合筛选、稳定排序、空值语义和按需列统计；
- 文件/字段/列数限制、无效路径、符号链接、非法编码、未闭合引号和临时空间不足；
- 流式导出、CSV 转义、拒绝覆盖、取消和源文件不变。

Panel 测试覆盖未连接、采样、索引、ready、空文件、警告和错误状态，以及文件选择、配置确认、分页、
搜索、筛选、排序、单元格详情、结构统计、导出和键盘交互。Kit 集成测试通过真实 Editor 装载三个插件，
打开包含引号换行的 fixture，验证 schema、查询和导出链路。

仓库验收包括：

- `@itharbors/kit-csv` manifest、`kit.json`、布局、窗口入口和插件清单合法；
- CSV Kit 被根 workspace、测试门禁、Kit 选择器和官方 Kit 发布映射识别；
- 三个插件 build/check 通过，CSV Kit 单测、运行时集成测试和 `npm run kit:check -- csv` 通过；
- 使用 `npm run dev -- --kit ./kits/csv` 可人工完成打开、浏览、筛选、排序、查看单元格和导出；
- 对一个显著大于浏览器合理内存的 fixture，浏览器端只接收当前页，Node 峰值内存不随总行数线性增长；
- 所有失败、取消、切换与退出路径都不会修改源文件或遗留打开句柄。

## 非目标与后续扩展

首版不包含原地编辑、另存为编辑副本、自动类型转换、公式、图表、数据透视、跨文件工作区、关联查询、
SQL、JSON/Excel 导入或远程 URL。后续能力必须保留源值无损和只读默认，并通过独立设计决定是否复用
临时索引、增加分析引擎或提供显式“另存为”。
