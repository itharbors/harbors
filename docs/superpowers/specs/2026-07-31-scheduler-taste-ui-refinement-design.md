# Scheduler 工具型后台界面优化设计

## 目标

在不改变 Scheduler 信息架构、表单字段顺序和服务交互协议的前提下，将现有界面优化为克制、清晰、高密度的开发者工具后台。界面应突出计划、下次执行和运行结果，同时让 hover、active、focus、loading、empty 和 error 状态组成完整反馈链路。

## 设计解读

- 页面类型：本地开发者工具的后台管理界面。
- 用户：需要快速判断计划状态并执行操作的 Node.js 开发者。
- 视觉语言：冷灰中性色、单一蓝色强调、轻层级、紧凑数据密度。
- 实现基础：现有原生 TypeScript 和 CSS，不引入 React 或第三方设计系统。
- 设计参数：`DESIGN_VARIANCE 4`、`MOTION_INTENSITY 3`、`VISUAL_DENSITY 7`。
- 改造模式：Redesign Preserve，保留 Harbors 现有的文案、语义和交互肌肉记忆。

## 现状审计

### 保留

- 页头、调度概览、计划表、运行记录和编辑抽屉的信息顺序。
- 表格语义、键盘焦点限制、表单字段级错和服务降级提示。
- 本地时区、计划状态和执行结果的语义色。
- 小屏幕下表格转纵向信息块的响应式逻辑。

### 退役

- 四张等宽白色指标卡与四条强调色边，它们在零数据时制造了过多容器和噪音。
- 过高的空状态表格行，它们浪费首屏空间且缺少就地操作。
- 几乎等权的行内操作按钮，用户难以快速区分主操作、管理操作和破坏性操作。
- 同时使用多个未定义或不完全统一的颜色、圆角和 hover 表达。
- 单独的旋转 loading 图形，它与最终后台布局形状不一致。

## 页面结构

### 页头

保留左侧标题和右侧服务状态、时区与新建操作。缩短面包屑的视觉存在感，让标题和简介成为第一层级。新建计划仍是页面唯一的实心主按钮。

### 概览统计带

将四张指标卡改为一个共享表面内的紧凑统计带，数字之间使用轻分隔线。数字保留等宽特征，语义色只在正在运行或确有失败时增强，零值默认保持中性。

### 计划与运行记录

两个区域使用同一表面、标题高度和表头规则。表格行 hover 仅通过浅色背景和左侧轻强调表达可聚焦性，不位移行内容。计划行中的“立即运行”使用浅蓝主操作样式，暂停和编辑使用安静按钮，删除只在 hover 或 focus 时显示红色风险感。

空状态缩短高度，使用标题、一句说明和就地“新建计划”按钮。运行记录空状态保持静态，不重复主操作。

### 编辑抽屉

保留原字段顺序，通过间距和轻分组标题区分“脚本”、“调度”与“错过处理”。输入框默认边界更安静，hover 只增强边框，focus 使用蓝色环。脚本目录浏览器使用和表单一致的表面，目录与文件通过排版和颜色区分，不使用 emoji。底部操作栏固定在抽屉底部。

## 设计令牌

- 主题：锁定为浅色工具主题，不在区域之间翻转主题。
- 强调色：全页只使用一组蓝色作为可操作和 focus 强调。绿、黄、红只用于真实状态。
- 中性色：冷灰色阶，正文、次要文本、边界和画布层级明确。
- 圆角：容器 `10px`，表单控件和按钮 `6px`，状态标记才使用全圆角。
- 阴影：仅抽屉和需要浮层层级的脚本浏览器使用淡色阴影。主页容器不使用投影。
- 字体：继续使用系统无衬线字体，路径、时间和数字使用系统等宽字体。

## 动效与交互状态

- 自动动画只保留抽屉进入、背景层显示和真实的运行中脉冲，用于表达层级或状态变化。
- hover 时只调整背景、边框、文字色和轻微阴影。表格行不位移，避免数据扫描时抖动。
- 按钮 active 使用 `translateY(1px)` 形成物理反馈。
- 所有键盘交互保留明确 focus-visible 环，并与 hover 保持同等信息量。
- `prefers-reduced-motion: reduce` 时取消动画和过渡，不影响状态可辨识性。

## 加载、空状态和错误

- 加载使用与页头、统计带和表格区域形状一致的骨架屏，不使用孤立旋转器。
- 计划空状态提供就地主操作，与页头按钮共用同一打开抽屉逻辑。
- 运行记录空状态说明产生记录的前置条件，不添加无效操作。
- 服务不可用保留独立恢复界面，后台写入失败保留页内降级提示。
- 表单错误仍与字段绑定，不改为短暂 toast。

## 响应式

- `900px` 以下页头换行，统计带改为两列。
- `760px` 以下表格保留现有的纵向信息块转换，行内操作保持可换行。
- `620px` 以下抽屉占满视口，新建按钮占满可用宽度，脚本选择器改为单列。
- 不使用 `height: 100vh`，需要视口高度时使用 `100dvh`。

## 代码边界

- 不改变 Scheduler Service、消息路由、快照数据结构和持久化逻辑。
- 不更改表单字段名、顺序、默认值或校验规则。
- 不引入新包。图标优先使用 CSS 字符或纯文字标签，不手写 SVG 路径。
- 允许对 Panel DOM 做小幅语义调整，用于统计带、骨架屏、空状态操作和表单分组。

## 验证

- Panel 测试覆盖新统计带、空状态主操作、加载骨架屏与现有抽屉交互。
- 构建后在本地 Scheduler 页面中走查默认、hover、focus、空状态和编辑抽屉。
- 使用桌面尺寸和小屏幕尺寸检查布局，并验证 reduced motion 分支。
- 运行 Scheduler 完整测试、Kit 定向检查和 `git diff --check`。
