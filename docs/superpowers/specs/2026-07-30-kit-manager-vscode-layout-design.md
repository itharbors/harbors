# Kit Manager VS Code 式主从布局设计

## 背景与目标

当前 Kit Manager 已具备在线仓库、安装进行态、启用/停用、历史版本切换、权限风险和即时热更新能力，但横向资源行同时承载身份、发布信息、本机版本、状态和操作，视觉权重接近，用户需要逐列阅读才能判断下一步操作。

本次改造参考 VS Code Extensions 的主从信息架构：左侧列表负责查找和判断状态，右侧详情负责理解、安装和管理选中的 Kit。视觉不复制 VS Code 主题，继续使用 Harbors 的深海港口语言和已验证安全语义。

页面面向安装和维护本机 Kit 的 Harbors 用户，单一任务是：快速找到一个 Kit，明确它是否可信、是否启用、当前使用哪个版本，并完成安装、启停、更新、切换或删除。

## 选择的方案

采用“固定列表 + 详情面板”的桌面主从布局，而不是继续扩展横向四列资源行，也不采用商城卡片墙。

- 列表像 VS Code Extensions：搜索和筛选固定在顶部，每个 Kit 使用紧凑条目，展示名称、摘要、版本和一个明确状态。
- 详情像 VS Code 的扩展详情页：标题区只保留主操作，概览、权限和版本记录分区呈现。
- 启停借鉴成熟插件管理器的显式状态操作，但使用 Harbors 文案和热更新行为。
- 历史版本不是常驻下拉框，而是详情内的“版本轨道”，这是页面唯一的高识别度设计元素。

该方案在宽屏下减少横向扫视，在窄屏下可自然切换为列表与详情单页导航，并且不要求新增 Registry、preload 或 IPC 字段。

## 视觉系统

颜色使用六个本地设计令牌：

- `--manager-canvas: #eef3f5`：冷雾画布；
- `--manager-surface: #ffffff`：列表和详情表面；
- `--manager-ink: #102a3a`：标题与主要文字；
- `--manager-muted: #667985`：辅助信息；
- `--manager-action: #2563eb`：选中态和主要操作；
- `--manager-risk: #d95f45`：原生代码与删除等危险语义。

成功状态从现有薄荷绿体系中派生，但不作为大面积背景。正文和控件使用系统无衬线字体；Kit 名称使用较紧凑的展示字重；版本、发布者和安全标记使用 `SFMono-Regular`、`JetBrains Mono` 或系统等宽回退。

现有 68px 深色泊位轨道保留品牌识别，但降低装饰刻度对比度。背景网格仅保留在空白画布，不穿透列表与详情表面。页面不使用外部字体、图片或远程资源。

## 页面结构

桌面宽度下页面由品牌轨道和一个两栏工作区组成：

```text
┌────┬────────────────────────────┬────────────────────────────────────┐
│ H  │ Kit 管理        [刷新]     │ CSV                      [已启用] │
│    │ [搜索 Kit……]               │ itharbors · 已验证                │
│    │ [全部] [已安装] [有更新]   │                                    │
│    │                            │ CSV/TSV 文件浏览、筛选与导出       │
│    │ ● CSV             已启用   │                                    │
│    │   CSV/TSV 浏览     v0.1.0  │ [概览] [权限] [版本记录]           │
│    │ ○ MySQL           已启用   │                                    │
│    │ ○ Notifications   已停用   │ 当前版本、权限摘要或版本轨道       │
│    │ ○ SQLite          有更新   │                                    │
└────┴────────────────────────────┴────────────────────────────────────┘
```

### 顶部与筛选

列表栏顶部包含页面名称、已安装数量、刷新按钮、搜索框和状态筛选。频道使用一个紧凑选择器或筛选菜单表达“稳定版/预览版”，不再为没有内容的稳定版保留大块空区域。

首期筛选状态为“全部”“已安装”“有更新”；如果快照中没有更新，不渲染误导性的更新数量。搜索匹配 Kit 名称、发布者和摘要，完全在已清洗的本地快照上执行。

### Kit 列表

每个 Kit 只占一个紧凑条目，包含：

- 名称和一行摘要；
- 当前可见频道版本；
- `已启用`、`已停用`、`未安装`、`有更新` 或 `异常` 中的一个主状态；
- 当前选中条目的钴蓝边线和低对比背景。

权限标签、历史版本选择器、删除按钮和重复频道信息不出现在列表中。键盘可使用 Tab 聚焦条目，Enter 或 Space 选中。切换选择不触发安装或其他副作用。

### Kit 详情

详情标题区显示 Kit 名称、发布者、验证状态、摘要和一个主要操作：

- 未安装：`安装`；
- 安装中：圈形进度和 `正在下载并验证…`；
- 已安装未启用：`启用`；
- 已启用：`停用`；
- 可更新：`更新`，当前启停状态作为次要操作保留。

标题区不同时展示多个同权重按钮。刷新和 Registry 状态属于页面级操作，不重复出现在 Kit 详情中。

详情正文分成三个标签：

1. `概览`：版本、频道、发布者和用途说明；
2. `权限`：逐项说明文件访问、网络访问、原生代码和随应用启动等能力，原生代码使用风险色；
3. `版本记录`：展示全部本地版本，并允许安装或切换。

删除属于低频危险操作，放在 `…` 菜单和详情底部危险区域；执行前继续使用现有确认文案与事务。

## 版本轨道

版本记录按 SemVer 从新到旧纵向排列，每个版本是一个泊位节点：

```text
● 0.1.0-preview.1    当前启用
│
○ 0.0.9              已安装        [切换]
│
○ 0.0.8              异常          [重试]
```

当前版本使用实心节点和状态文字；普通历史版本使用空心节点；异常版本使用风险色。选择版本不会立即产生副作用，用户必须点击明确的“切换”或“重试”。停用后保留全部版本，并在最近启用版本上提供“启用”。

版本轨道只使用 CSS 线条与节点，不添加图片或图标依赖。它编码真实的版本顺序和状态，不是装饰性时间线。

## 状态与数据流

`createKitManagerView` 继续消费现有清洗后的快照，并保留为唯一 Renderer。View 新增纯本地 UI 状态：

- 当前搜索词；
- 当前筛选；
- 当前选中的 Kit ID 和频道；
- 当前详情标签。

首次渲染默认选择排序后的第一个已安装 Kit，否则选择第一个可见 Kit。刷新后若原选择仍存在则保持选择；否则选择新的第一个可见条目。搜索或筛选导致当前 Kit 不可见时选择第一条可见结果；没有结果时详情显示带方向的空状态。

安装、启用、停用、版本切换和删除继续调用现有 API。进行中操作只锁定可能产生冲突的操作控件，列表选择和查看详情保持可用。操作完成后重新获取快照，并以返回数据重建列表和详情，不在 Renderer 维护第二份安装事实。

Registry 加载、缓存、离线和失败状态继续由页面级状态条表达。错误信息说明失败动作和恢复方式，不使用仅有“失败了”的模糊文案。

## 响应式与可访问性

- `>= 980px`：列表约 320px，详情占剩余空间；
- `< 980px`：列表约 280px，详情自适应；
- `< 720px`：默认显示列表，选中 Kit 后进入详情，提供明确返回按钮；
- 所有主要操作和标签页使用语义按钮，选中态分别使用 `aria-selected` 或等价语义；
- 安装状态使用 `aria-live`，主区域继续维护 `aria-busy`；
- 焦点环使用可见的操作蓝外圈，不只依赖颜色区分状态；
- `prefers-reduced-motion: reduce` 下停止圈形进度动画和面板过渡。

## 测试与验收

自动化测试先于生产修改，并至少覆盖：

- 默认选择和刷新后的选择保持；
- 搜索、状态筛选和频道筛选；
- 列表只呈现紧凑摘要，不渲染版本下拉或删除按钮；
- 详情三个标签及权限风险语义；
- 安装、启用、停用、更新、切换、重试和删除调用现有准确参数；
- 安装 pending 时的圈形进度、禁用边界和成功/失败清理；
- 版本轨道排序、当前/异常/停用状态；
- 空结果、离线缓存、无稳定版和窄窗口结构；
- CSP、本地资源、键盘焦点与 reduced-motion 约束不回退。

开发阶段使用 Web/JSDOM 完成交互和桌面/窄屏视觉走查。完成后运行 Manager 聚焦测试与仓库完整检查，最后启动 Electron 原生窗口验证实际尺寸、焦点、安装和热停用行为。

## 非目标

- 不修改 Kit Registry 格式、签名验证或发布策略；
- 不新增 preload/IPC 权限或真实字节下载进度；
- 不改变 Framework 热更新和错误恢复事务；
- 不加入评分、下载量、截图、推荐算法或远程字体；
- 不在本次引入多选、批量安装或批量停用。
