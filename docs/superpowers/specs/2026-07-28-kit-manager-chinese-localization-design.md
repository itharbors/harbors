# Kit Manager 中文化设计

## 目标

将 Kit Manager 当前面向用户的固定英文文案统一改为简体中文，让中文用户能够直接理解安装、激活、回滚、权限风险和 Registry 状态。保留 `ITHARBORS`、`Kit`、`CSV`、`SQLite`、`MySQL` 等品牌与技术名称。

## 范围

中文化以下界面内容：

- 页面标题、引导语、分区标题和页脚说明；
- Registry 加载、在线、缓存和不可用状态；
- Kit 可用、已安装、已激活、等待重启和已标记异常等状态；
- 安装、更新、激活、重试和回滚按钮；
- 网络、文件访问、原生代码和开机启动权限标签；
- 原生代码安装确认、安装进度、安装完成、激活和回滚提示；
- 本地安装、Registry 外安装和权限信息缺失等回退文案。

不翻译 Registry 提供的 Kit 名称、发布者、摘要、版本号和服务端返回的原始错误消息，避免改变外部数据含义或掩盖诊断信息。

## 实现方式

保持现有单语言页面架构，不引入语言切换器或 i18n 运行时。直接更新 `scripts/kit-manager.html` 的静态文案以及 `scripts/lib/kit-manager-view.mjs` 的动态文案，并把页面语言声明从 `en` 改为 `zh-CN`。

Stable 和 Preview 在用户界面分别显示为“稳定版”和“预览版”；代码内部的 `stable`、`preview` 通道标识和 IPC 数据结构保持不变。Registry 在用户界面显示为“Kit 仓库”，代码与错误对象中的 Registry 技术标识保持不变。

## 错误与安全边界

原生代码确认弹窗必须明确说明其拥有较高的本机访问权限，并要求用户确认具体版本。未知异常继续通过现有安全回退文案展示；来自服务端且已净化的错误消息保持原文，以便诊断。

页面继续使用 `textContent` 创建动态内容，不引入远程资源、内联脚本或 HTML 注入路径。现有内容安全策略和可访问性结构保持不变。

## 测试与验收

先更新视图测试，要求页面声明 `lang="zh-CN"`，并覆盖关键静态文案、状态、按钮、权限标签、确认弹窗和操作反馈的中文结果。测试必须先因现有英文文案失败，再修改生产文件使其通过。

完成后运行 Kit Manager 视图测试、相关 Manager 测试和全仓检查。最后启动 Electron，人工确认页面首次加载、预览区展开以及已安装 Kit 的状态均为中文，同时保留品牌与技术名称。
