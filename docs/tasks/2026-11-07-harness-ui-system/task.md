## 背景与问题

Harness 各面板的颜色、字体和控件样式各自维护，缺少统一规范。用户选定深色视觉方向，要求保留现有布局。

## 目标

建立 Harness Kit 的 UI 主规范和首批原生控件展示面板，利用宿主现有主题与基础样式机制，在现有面板中应用首批视觉规范，供用户验收。

## 范围

Harness Kit 内的规范、主题、UI 入口与展示面板；Framework 的 Kit 描述、资源装配及直接 Panel runtime 加载机制；首批界面统一。

## 非目标

重新设计布局、增加全局页头页脚、改动业务消息协议、嵌套面板的 UI 自动注入或引入桌面宿主。

## 验收标准

- 有中文主规范，定义深色视觉方向、基础 token、组件及交互状态和插件接入方式。
- 在工作台可打开展示面板；真实直接 Panel 展示 Kit UI 入口注册的元素及状态，不要求改动默认布局。
- 首批聊天和会话列表视觉与规范一致；业务交互保持可用。
- Kit 声明单一 UI JS 入口；Framework 在每个直接 Panel iframe 中先准备 runtime、等待入口加载注册，再加载并启动插件 Panel。插件无需导入 Kit 私有 UI 包；未声明入口的 Kit 行为保持不变。
- Kit UI 资源的构建、打包和 session/Kit 边界可验证；注册失败有明确表现且不会悄悄执行依赖该 UI 的插件。嵌套面板不在本期覆盖范围。
- 完成 Kit 相关验证和真实 Web 浏览器验收，记录未覆盖项。
- 设置面板在窄宽下能直接辨认并选中“界面规范”，操作后显示的页面和独立打开目标一致。
- 打开、关闭、最小化或恢复浮动面板时，已有工作台面板及其他未受影响的浮动面板不重建；当前设置选择、输入草稿和滚动状态保持。

## 约束

Kit 为装配边界，插件保持独立，通过消息交互；不得依赖其他插件私有资源或 Framework 私有源码。用户明确授权本方案涉及的 Framework 扩展，使用 Web 宿主，保留工作区已有改动。

## 需求变更

用户选定深色方案，明确不改布局；认可 Kit 负责规范和装配、插件提供展示面板，并授权实现后由用户验收。

2026-11-08 用户确认第一期优先使用原生 HTML 及宿主已有的基础样式注入，让业务插件不显式引用 Harness Kit 私有 UI 包。主规范供人阅读；展示页为示例。复杂组件及必要的 Framework 扩展不在本期自动实施。

随后用户明确授权实施新方案：Kit 声明一个 UI JS 入口，Framework 复用 Panel runtime 的加载链，在直接面板中按 Framework runtime → Kit UI → Plugin Panel 的固定顺序执行；不引入跨 Framework/Kit 的排序 index，不处理嵌套面板。

为了从现有工作台看到真实组件，Settings 直接面板提供通用操作以独立打开当前设置页；不向嵌套 iframe 注入 UI，也不新增组件间业务消息协议。

用户验收指出无法辨认“界面规范”入口，且打开独立浮动面板时整个工作台重载、设置回到 Agent；用户明确授权修复并再次验收。维持既有工作台三栏及当前工作区，不重置已有改动。
