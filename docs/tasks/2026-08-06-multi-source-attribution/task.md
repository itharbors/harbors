# 修复 Agent Guard 多来源流量归因

Task ID: `2026-08-06-multi-source-attribution`
Type: `bug`

## 背景与问题

修复 Agent Guard 将客户端家族等同于模型服务来源的问题。Claude 与 Codex 的网络连接必须按实际可验证的远端端点归因；无法确认来源时显示未知来源，而不是套用该客户端的全局默认服务商。

当前服务为 Claude 和 Codex 各读取一份全局配置，并把这份配置应用到该家族的所有进程。这样会把所有 Codex 流量标成全局 `model_provider`，也会把所有 Claude 流量标成全局 `ANTHROPIC_BASE_URL`。同一客户端通过不同 provider、网关或进程级覆盖运行时，来源会被错误合并。

本机诊断还确认部分 Claude/Codex 后台进程因可执行名称带角色后缀而被观察器提前过滤，导致活跃任务统计偏低。

## 目标

- 分离“客户端家族”和“模型服务来源”两个维度。
- 从客户端配置中发现所有安全、可解析的候选 HTTPS 端点。
- 仅在远端地址与候选端点 DNS 证据唯一匹配时标注具体 provider/hostname。
- 无匹配或多个候选共享地址时归为未知来源，不错误套用全局默认 provider。
- 同一客户端同时访问不同已确认端点时，在流量面板显示为不同路由。
- 纳入已知 Claude/Codex 后台进程名称，并保持进程控制的保守安全边界。

## 范围

本 Task 覆盖 Agent Guard Kit 的 Claude/Codex 配置发现、进程观察、实时连接归因、端点路由展示，以及相应自动化测试和 Web 验收。

## 非目标

- 不读取或持久化进程命令行、环境变量、令牌、请求正文或 TLS 内容。
- 不通过不可靠的 IP 反查猜测任意第三方服务商。
- 本次不新增尚无配置、会话和安全控制语义的 Agent 家族。
- 不改变流量熔断策略阈值。

## 验收标准

- Codex 配置中的多个 `model_providers` 端点都可参与连接归因。
- Claude 自定义端点与 Anthropic 官方端点可同时作为候选来源。
- 唯一 DNS 匹配产生对应 provider/hostname；无匹配或歧义匹配产生 `unknown` 来源。
- 端点路由仍按 `agent + provider + hostname` 隔离累计数据。
- Claude/Codex 带已知后台角色后缀的进程可被观察，但不会因此放宽到任意相似名称。
- 新增聚焦测试覆盖多来源、未知来源、共享地址和后台进程识别。
- Agent Guard Kit 全量测试、构建、校验与打包通过。

## 约束

改动必须限制在 `kits/agent-guard` 与本 Task 的正式档案内。来源归因必须保持隐私优先和保守失败：不得读取敏感进程上下文，证据不足时不得猜测 provider，也不得让未知来源进入自动控制路径。

## 需求变更

浏览器验收发现多路由会压缩并裁剪历史区域，因此在原验收范围内补充了多路由纵向滚动布局修复；其他需求未变化。

实机回归发现 ChatGPT 桌面端内置 Codex 使用 `chatgpt.com`，而不是 Codex CLI 默认的 `api.openai.com`。该官方路由属于现有 Codex 来源识别范围，补充为 OpenAI 候选端点并要求通过 DNS 证据确认，不能回退为按客户端默认套用来源。

浏览器验收进一步明确多路由布局：观测路由较少时必须按内容自然收缩，不预留固定空白；较多时最多占总览内容区的 50%，超出内容仅在路由列表内部滚动，历史区域持续使用剩余空间。
