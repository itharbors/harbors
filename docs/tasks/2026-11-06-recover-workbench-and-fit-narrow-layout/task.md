# 工作台初始化恢复与窄屏布局

Task ID: `2026-11-06-recover-workbench-and-fit-narrow-layout`
Type: `bug`

## 背景与问题

Framework 走查发现两项问题。Kit 缺少构建产物导致初始化请求失败时，工作台停留在加载状态。Harbors Harness 默认左右栏分别为 280 和 300 px，在 390 px 竖屏将中央列挤为零，320 px 时部分右侧 Tab 超出视口。

## 目标

初始化失败有可见状态和重试入口，故障恢复后可继续进入。窄屏初始展开时，固定宽度侧栏允许适度缩小，中央工作区和侧栏 Tab 保持可见。横屏恢复原尺寸。

## 范围

Framework Client 的 EditorApp 初始化、横向布局尺寸与回归验证。浏览器使用隔离 Default 和 Harness 作为夹具。

## 非目标

修改 Kit 默认布局或服务端协议、处理各 Plugin 内容的内部响应式布局、调整纵向固定工具栏尺寸。

## 验收标准

- 缺少构建产物时显示初始化失败和重试按钮，补齐后同页重试可进入工作台。
- 390 和 320 px 初始展开布局中央有可用宽度，原超出视口的右侧 Tab 可点。桌面、横屏尺寸、横竖屏往返、侧栏收起、拖放和分隔条调整通过回归。
- 提交后自测通过再推送到远端 `main`。

## 约束

遵循 [测试指南](../../guides/testing.md)，仅在隔离 Web 宿主中验证，避免动真实会话。保留固定 simple Panel 和纵向布局的尺寸语义。

## 需求变更

用户要求修复 Framework 走查中的两项问题，先提交，再进行本地自测，测试通过后直接推送远端。继续当前 `main`，推送包含三笔尚未推送的布局相关祖先提交。
