# 本机 Web 文件打开

Task ID: `2026-08-07-local-web-file-open`
Type: `feature`

## 背景与问题

统一文件选择运行时目前在 Web 中能够展示原生选择器，但普通浏览器无法提供绝对路径，选择完成后固定提示只能在桌面版使用。用户期望 localhost 上运行的 Harbors 能直接使用所选文件，并要求桌面与 Web 保持相同选择交互。

## 目标

让本机 Web Harbors 可以通过与 Electron 相同的浏览器原生选择器打开用户明确选择的本机文件，同时拒绝跨机器远程文件传输。

## 范围

- 保留 `context.file.openLocal()` 作为 Panel 的统一打开入口。
- Electron 继续通过 `webUtils.getPathForFile()` 返回原始绝对路径。
- 本机 Web 将用户主动选择的文件流式暂存到 Harbors 管理的临时目录，并向 Kit 返回暂存文件绝对路径。
- 服务端校验请求来自 loopback Web Origin；远程访问返回稳定错误且不读取文件内容。
- 限制单文件大小，使用受控文件名、独占临时目录和原子写入，并在会话删除或服务停止时清理。
- 暂存文件移除写权限，SQLite 初始连接保持只读，避免修改用户选择的原文件。
- 补充共享运行时、路由、清理和远程拒绝测试，并以 SQLite Web 页面完成浏览器验收。

## 非目标

- Web 新建本地文件、覆盖或写回浏览器所选原文件。
- 目录选择、通用上传管理器或后台静默上传。
- 允许通过局域网地址、代理域名或其他远程 Origin 使用本机文件暂存。

## 验收标准

- Electron 与 Web 点击“打开数据库”时继续出现同一种浏览器原生文件选择窗口。
- 通过 `localhost` 或 loopback 地址访问时，SQLite 文件选择后能够只读打开并浏览。
- 通过非 loopback Origin 访问时，服务端在读取请求体前拒绝，并展示明确的远程访问提示。
- 取消选择无副作用；超限、无效会话和中断上传不会留下可见临时文件。
- 会话删除和服务正常关闭会清理对应暂存文件。

## 约束

- 文件内容只有在用户明确触发选择器并选中文件后才可传输。
- 客户端宿主标志不能作为远程安全边界；服务端必须验证浏览器 Origin。
- 共享运行时仍返回 `Promise<string | null>`，现有 Kit 不新增宿主分支。
- SQLite、CSV 等 Kit 继续把返回路径视为不可信输入并执行自身文件校验。

## 需求变更

需求最初被理解为 SQLite 单 Kit 的浏览器兼容缺陷；用户随后明确要求 Electron 与 Web 选择窗口一致，并仅允许同机 Web 打开、拒绝跨机器远程访问。可靠的 Origin 判定、流式暂存与生命周期清理属于共享 Framework，因此改由本共享 feature Task 承接；原 SQLite Kit Task 在设计阶段按边界阻断。
