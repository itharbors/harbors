# 视口切换后的布局宽度漂移

Task ID: `2026-11-06-viewport-layout-width-drift`
Type: `bug`

## 背景与问题

用户报告横竖屏往返后布局宽度发生累计变化。真实 Harness 在 Chromium 模拟中，纯视口往返未改写缓存，同尺寸可恢复。先在横屏拖动分隔条，再切窄屏并轻触分隔条，未发生位移也会重算全部比例，将临时测得的窄屏宽度写回。缓存的两个侧栏宽度从 310、300 变为 140.83、136.3 px，下一次重新渲染会应用这些缩小值。

## 目标

自动视口变化或无位移的分隔条手势保留用户设置的布局尺寸。实际拖动按现有方式调整和保存尺寸。

## 范围

Framework Client 的分隔条拖拽结束、布局尺寸保存及对应验证。

## 非目标

变更 Kit 布局、最小尺寸规则或实现面板收起。面板收起单独提交。

## 验收标准

- 模拟多次横竖屏往返，返回同尺寸时宽度和布局缓存保持一致。
- 已拖动并保存的布局在窄屏轻触分隔条后，宽度缓存保持不变。回到横屏并刷新后仍恢复拖动后的宽度。
- 有位移的鼠标及触屏拖动仍可调整和保存，抬起后结束广播和遮罩清理正常。

## 约束

按 [布局与窗口模型](../../architecture/layout-model.md#resize) 和 [测试指南](../../guides/testing.md) 验证 Framework Client 与隔离 Harness Web 宿主。

## 需求变更

用户要求先修复宽度漂移，再单独处理双击 Tab 收起面板，每项各提交一笔供审核。沿用当前 `main` 的开发环境。
