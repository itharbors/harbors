# 修复 Agent 本地工具安全边界与错误语义

Task ID: `2026-08-21-secure-agent-tools`
Type: `bug`

## 背景与问题

Agent Plugin 提供文件、网络和 Bash 工具给模型调用。当前本地文件工具主要依赖字符串形式的 workspace 路径检查，遇到符号链接、路径规范化或移动操作时，可能绕过检查访问 workspace 之外的文件；这会把模型可操作的范围扩大到用户未授权的位置。

`web_fetch` 当前没有完整拒绝 loopback、私网、link-local 和云元数据地址的 SSRF 防护，且重定向后的地址与响应体大小没有形成逐跳、有限的安全边界。恶意或失控的 URL 可能因此访问宿主内部服务，或者消耗过多内存和网络资源。

Bash 工具对非零退出、信号终止和超时的结果表达不一致，部分失败可能被记录成成功的工具结果。模型和 Chat UI 无法据此可靠地区分成功、失败、取消和超时，容易继续基于错误结果工作。

## 目标

- 将文件工具的所有路径解析和文件系统操作限制在授权 workspace 内，并防止通过符号链接和等价路径越界。
- 让 `web_fetch` 对初始地址和每一跳重定向执行 SSRF 地址校验，并以有界方式读取响应。
- 统一 Bash 工具对成功、非零退出、信号终止和超时的结果语义，确保失败不会伪装成成功。
- 为上述边界补充可复现的 Agent Plugin 聚焦回归测试，保持既有正常用例行为。

## 范围

- `Agent Plugin` 内的文件工具：路径规范化、workspace 边界判定、read/write/move/delete 等操作，以及符号链接相关处理。
- `Agent Plugin` 内的 `web_fetch`：目标地址解析、DNS/IP 安全判定、重定向限制、响应体大小/读取限制和对应错误返回。
- `Agent Plugin` 内的 Bash/命令执行工具：退出码、信号、超时、取消和工具结果状态的映射。
- 上述工具的单元测试、集成测试和必要的错误类型/文档更新。

## 非目标

- 不修改 Preview Plugin 的网络访问实现；不以 Preview 的实现替代 Agent Plugin 的安全边界。
- 不修改 Model Service、Chat Panel 或 Framework 的请求协议、权限模型和运行时 API。
- 不实现完整 OS 沙箱、容器隔离、跨 workspace 授权或新的网络代理服务。
- 不改变工具的正常业务能力、命令解释器选择、workspace 配置来源或公开消息名称；仅修复越界和失败语义。
- 不处理 Agent Turn/Item 事件协议、真正流式输出、运行时存储和 Kit 装配等其他改进项。

## 验收标准

- 文件工具对 workspace 内的普通文件和目录保持原有读、写、移动、删除能力；对包含 `..`、绝对路径、空路径和等价规范化路径的越界访问统一拒绝。
- 文件工具在 workspace 内存在指向 workspace 外的符号链接时，read、write、move、delete 及相关目录操作均不能通过该链接触达 workspace 外目标；符号链接检查不能只依赖未经解析的字符串前缀。
- 覆盖不存在目标、父目录含符号链接、目标为符号链接和移动源/目标跨边界的回归测试，并证明拒绝结果不会执行部分越界操作。
- `web_fetch` 拒绝 loopback、RFC1918 私网、link-local、保留/未分配本地地址及云元数据地址；IPv4、IPv6、域名解析到上述地址的场景均有测试。
- `web_fetch` 对每一跳 HTTP 重定向重新解析并校验目标地址，禁止从公网地址重定向到受限地址；超出允许重定向次数时返回明确失败。
- `web_fetch` 对响应体采用明确的最大字节数和读取/超时限制，超限、截断、网络错误和无效响应均返回失败，不能在限制前将无限响应完整载入内存。
- Bash 命令退出码为零时返回成功；非零退出码、被信号终止和超时分别返回失败结果，并保留可诊断的退出信息。
- Bash 超时后进程及其必要的子进程被终止，不会继续写入成功结果；取消、超时和普通失败不会被标记为成功或静默吞掉。
- 文件工具、`web_fetch` 和 Bash 的拒绝/失败结果使用稳定、可断言的错误类别或字段，既能供 Agent 继续处理，也不会泄露不必要的宿主敏感信息。
- Agent Plugin 的聚焦构建、类型检查和新增回归测试通过；既有 Agent 工具正常路径测试通过。
- 修改范围仅位于 Agent Plugin 及本 Task 的正式档案，不引入 Preview、Model Service 或 Framework 的源码变更。

## 约束

- 安全检查必须 fail closed：无法解析真实路径、DNS 结果或重定向目标时拒绝操作，不能退回字符串前缀或“先访问后校验”。
- workspace 边界判断必须同时考虑已有路径和将要创建的目标路径；避免 TOCTOU 窗口导致校验通过后操作到边界外。
- 网络地址校验必须覆盖解析得到的全部地址，并在连接/重定向过程中保持校验；不得仅按 URL 字符串或域名后缀判断公网性。
- 所有文件、网络和进程资源都必须有界；限制值应集中定义并可由测试验证，错误路径也必须释放句柄、进程和响应资源。
- 保持现有 Web 宿主约束，不增加 Electron、桌面窗口、原生 IPC 或 OS 专属宿主假设。
- 遵守 Plugin 边界：实现和验证在 Agent Plugin 内闭环；如确实需要修改共享 Framework 或其他 Plugin，先暂停并重新确认范围，不在本 Task 中越界修改。
- 不修改 `status.json` 的 schema 或手工写入状态；Task 状态仅由任务 CLI 管理。

## 需求变更

- 本 Task 来源于 Codex 与 Agent Kit 的只读架构审计，原先识别的安全与错误语义问题经归并后形成独立的 Agent Plugin bug Task。
- 用户确认将该问题作为独立 Task 建档；本 Task 只覆盖本地文件工具、`web_fetch` 和 Bash 三类边界，不携带其他协议、流式或存储改进。
- 实施过程中若发现修复必须跨出 Agent Plugin 目录，应先记录阻塞原因并重新取得范围确认，不以临时修改其他模块的方式完成验收。
