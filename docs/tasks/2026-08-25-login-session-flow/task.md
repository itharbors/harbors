# 将工作台入口改为登录式用户与 Session 流程

Task ID: `2026-08-25-login-session-flow`
Type: `feature`

## 背景与问题

现有入口把用户与 Session 并排放在工作台选择页，表现为管理表单。用户反馈这不是目标体验：用户身份应先于工作台出现，选择用户要接近系统登录窗口；Session 应作为进入工作台前的第二步，而不是和用户、Kit 同屏竞争注意力。

## 目标

1. 将裸入口改为清晰的三步流程：选择用户 → 选择可继续的 Session（可跳过）→ 选择工作台。
2. 用户以头像/图标卡片呈现，整体体验接近系统登录窗口，而不是表单下拉框。
3. Session 使用独立列表呈现；用户可以选择既有 Session，也可以不选择。
4. 未选择 Session 时，点击“继续选择工作台”即由 Server 自动创建属于当前用户的新 Session；进入工作台选择页时 Session 已经确定。
5. 已选择 Session 时，进入 Kit 继续复用该 Session。

## 范围

- `packages/client` 的工作台入口结构、交互状态、文案、响应式样式、键盘与焦点行为及测试。
- 必要的 `packages/server` workbench API 调用适配与聚焦测试；新增受保护的用户删除能力，但不扩展身份模型。
- 普通开发栈与 Web Host runner 的网络监听装配：Gateway 对所有 IPv4 网卡开放，上游 Server 与 Client 继续只监听回环地址。
- 本 Task 档案和必要的产品/架构说明更新。

## 非目标

- 不改变 `User 1:N Session`、授权设备绑定或 Session owner 安全模型。
- 不新增 Project、密码登录、SSO、头像上传或云账号系统。
- 不把用户图标做成可配置个人资料；首版使用稳定生成的图标/首字母视觉。
- 不修改 Kit 或 Plugin 业务实现。

## 验收标准

1. 入口第一屏以登录窗口式用户卡片展示可选用户，不显示 Session 与 Kit 列表。
2. 选择用户后进入 Session 屏，展示该用户已有 Session 列表；若存在 Session，默认选中最近使用的一项，并提供明确的“不选择，创建新 Session”路径。
3. Session 屏和工作台选择页都在内容顶部提供清晰、位置一致的“上一步”按钮；按钮说明将返回选择用户还是选择 Session，返回后保留可恢复的选择状态。
4. 选择已有 Session 后，Kit 链接或进入动作复用该 Session。
5. 不选择 Session 时，点击“继续选择工作台”会先创建属于已选用户的新 Session，再进入工作台选择页；随后点击 Kit 只负责进入，不再创建 Session。
6. 刷新时若 URL 包含有效 Session，可恢复其 owner 用户和已选 Session；无有效 Session 时从用户选择开始。
7. 用户/Session 空状态、加载失败和创建失败均提供清楚、可恢复的动作。
8. 支持键盘选择、可见焦点、窄屏布局与 reduced-motion。
9. 用户卡不使用背景色和位移动效；点击“新用户”前后，卡片容器、加号、尺寸和网格位置完全不变，只把“新用户”名称文字原位替换为同宽、同高、同字号的透明输入框。重命名同理；支持 Enter 确认、Escape 取消和失败重试。
10. Client 聚焦与全量测试、必要 Server 测试、类型检查、`git diff --check` 通过，并在唯一 Web Host 中完成浏览器端到端验收。
11. 用户输入框失焦即取消编辑并恢复原名称；用户卡的“改 / 删”动作只在 hover、键盘 focus-within 或触摸设备上显示。删除必须原位二次确认；只有无 Session、无授权设备绑定的用户可删除，不做级联清理。
12. Session 列表提供 hover、键盘 focus-within 或触摸设备可见的紧凑删除动作；删除必须原位二次确认。删除成功后立即移除列表项；若删除当前选中 Session，先清空原选择，再在仍有 Session 时默认选中最近使用项，失败则保留原项和选择。
13. 未授权的远程入口复用登录式“选择使用者”页面，只展示已有用户头像卡片，不提供新建、重命名或删除用户；用户选择完成前不得创建待审批记录。
14. 远程用户点击头像后，显式提交“设备 + 用户”授权申请并进入等待审批页面；等待页展示已申请的用户与设备摘要，只轮询授权状态，不允许读取该用户的 Session 或工作台上下文。
15. 远程公开接口仅返回渲染用户卡所需的 `userId` 与 `displayName`，不返回 Session、时间戳或其他工作数据；未知/已删除用户不能创建授权申请。
16. 本机授权管理页明确展示远程设备申请登录的用户，审批默认且仅绑定该申请身份；若用户仍有待审批设备，则禁止删除该用户，避免形成无法批准的悬空申请。
17. 普通 `pnpm dev` 与 production `pnpm start` 默认使用同一正式数据根 `~/.harbors`；运行模式本身不隐含数据隔离。两个入口均可通过同语义的 `--data-root <absolute-path>` 一次性切换 Session 数据库、配置存储和 Plugin data/cache/temp，禁止只切换其中一部分。
18. 隔离 Web Host runner 默认继续使用自动创建的临时数据根，并允许调用方显式传入持久 data root；停止 runner 时只能删除其自己创建的临时目录，不能删除调用方提供的数据根。

## 约束

- 仅支持 Web Host，不引入桌面宿主假设。
- 对外网络入口只允许 Gateway；Server、Client 和其他上游端口不得因开放 Gateway 而同时暴露。
- 未授权远程设备可以在公开的精简用户列表中选择申请身份；完成授权后，其身份固定为设备绑定用户，不能在工作台入口切换成其他用户。
- 未选择 Session 不是空错误状态，而是“进入工作台选择页时创建新 Session”的有效选择；工作台选择页始终已经绑定 Session。
- Session 创建继续由 Server 分配 opaque ID，Client 不自行生成。
- `HARBORS_DATA_ROOT` 是统一的数据根；`DB_PATH` 与 Plugin 细分 root 仅保留为更高优先级的底层兼容覆盖，不作为普通 Dev 的首选入口。
- 自定义 data root 必须为绝对路径；显式自定义根不从仓库旧 `.data` 路径自动迁移，避免“隔离启动”意外导入正式或遗留数据。
- data root 不隔离 OS Keychain；同一 data root 同时只应由一个 Host 使用，避免 Plugin 文件与运行时状态出现多进程所有权冲突。
- `status.json` 仅通过 Task CLI 更新。

## 角色

- owner：当前主 Agent，负责范围、实现验收与 Task 状态。
- reviewer：独立 sub-agent，负责交互层级、状态恢复与回归审查。
- approver：当前用户，负责确认登录式入口方向与交付方式。

## 需求变更

- 用户明确否定并排下拉框版本，要求先选择图标化用户，再选择 Session，最后选择工作台。
- Session 选择改为可选；用户进一步澄清：不选时应在点击“继续选择工作台”、进入工作台选择页之前创建新 Session，而不是等到点击具体 Kit。
- 用户进一步指出选择错误时必须能还原；返回动作不能只是弱化的管理文案，需要明确表现为“上一步”，并说明返回目标。
- 用户在 Web Host 中确认“新用户”点击无效；根因范围收敛到原生 prompt 交互不可靠，创建与重命名改为页面内编辑表单。
- 用户否定额外展开的大型编辑面板，要求直接把被点击的“新用户”卡变成输入框；创建和重命名均改为卡片原地编辑。
- 用户再次澄清“样式不变”的含义：不能把整张卡变为编辑容器，只允许名称文字节点变成 input，加号与卡片几何必须保持原样。
- 用户指出卡片仍有 hover 背景且点击会位移；删除卡片背景与 `translateY`，统一名称文字和 input 的盒模型，确保交互前后零位移。
- 用户继续指出 Host masthead 的上下留白不对称，以及输入框出现时不应带轮廓；masthead 改为对称垂直内边距，输入框只保留聚焦下划线，不显示 outline 或 glow。
- 用户要求输入失焦后退出编辑，并认为长期显示完整“重命名 用户名”不适合再加入删除动作；用户操作收为 hover/focus 时出现的“改 / 删”紧凑按钮，删除在原位确认。
- 用户进一步要求 Session 也可删除；沿用紧凑 hover/focus 动作与原位确认，并复用现有 Session 删除接口完成运行时和持久状态清理。
- 用户要求有 Session 时默认选中一个；按“最近使用”排序并默认选中首项，同时保留“不选择，创建新 Session”作为显式覆盖。
- 用户指出工作台步骤的返回按钮跑到中间；统一工作台页返回导航与工作台列表的 860px 内容宽度，使两者左边缘对齐。
- 用户确认 Web Host 不应限制为仅回环访问，要求监听所有地址；实现必须只公开 Gateway，保留上游回环隔离与授权边界。
- 用户认为现有远程授权页难看，要求远程入口与本机一样先选择用户，但不能新建用户；选择后进入等待审批页。由此将“匿名访问即自动产生待审批”改为“选择已有用户后显式产生待审批”，且匿名侧只公开用户卡所需最小字段。
- 用户确认开发模式默认也应读取正式数据，是否读取正式数据应由启动参数控制；因此将“development / test”运行模式与“persistent / custom data root”解耦，普通 Dev 默认 `~/.harbors`，隔离验收显式使用临时 root。
