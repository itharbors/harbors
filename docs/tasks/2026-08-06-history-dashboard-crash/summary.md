# 修复 Agent Guard 历史监控不可用与大数据崩溃 实现总结

## 最终结论

已修复历史状态在约 12 万条记录下的调用栈溢出，以及模型用量按事件、指标和时间桶重复全量扫描导致的后台进程退出。Agent Guard 0.1.0-preview.5 的构建、完整测试、清单校验和浏览器网络历史验收均通过。

## 需求完成情况

- 网络历史查询与状态查询在本机现有约 12 万条历史记录上恢复正常，界面不再进入历史数据不可用状态。
- 模型用量查询改为单次事件扫描并按桶累加，同一真实数据集可稳定返回汇总和趋势结果。
- 网络字节、模型 token、来源、覆盖率和缺口语义保持不变。
- 新增 12.5 万条状态记录和 3 万条模型用量事件的回归测试。
- Agent Guard 聚焦构建、198 项完整测试、Kit 清单校验和 Web 浏览器验收通过。

## 主要改动

- 历史状态和压缩边界改为迭代计算最早/最晚时间，不再把大数组展开为函数参数。
- 模型用量聚合器在去重的同时按维度、指标和时间桶累加，复杂度从事件数与桶数相乘的重复扫描降为以事件数为主的单次扫描。
- 将 Agent Guard Kit 版本从 0.1.0-preview.4 提升到 0.1.0-preview.5。

## 关键决定

保留现有查询响应的 2,000 点预算、维度排序、指标顺序和完整覆盖语义，只替换内部求极值与聚合算法，避免修复过程中改变用户看到的统计口径。

## 验证结果

- `npm run test:toolchain`：通过，生成仓库与 Kit 构建工具链。
- `npm run build`（`kits/agent-guard`）：通过，构建 0.1.0-preview.5 与 2 个插件。
- `npm test`（`kits/agent-guard`）：29 个测试文件、198 项测试全部通过。
- `npm run kits:validate -- kits/agent-guard`：通过，校验 38 个 Kit 文件。
- 本机现有历史数据复测：状态查询 124 ms、24 小时网络查询 209 ms、24 小时模型用量查询 231 ms，均成功返回；修复前状态查询抛出 `Maximum call stack size exceeded`，模型查询导致进程退出。
- `npm run dev:web -- --kit <Agent Guard 工作树路径>`：浏览器中网络历史正常显示且没有 Agent Guard 应用异常。浏览器控制层未能触发嵌套面板按钮点击，因此模型用量交互由完整面板测试和真实数据后台查询覆盖。

## 影响与风险

改动仅位于 Agent Guard Kit 和本 Task 正式档案。新算法仍需把当前保留范围的原始历史读入内存，但不再产生与事件数乘以时间桶数成比例的重复临时数组；响应点预算与持久化格式未变。

## 偏差与遗留

浏览器自动化未完成模型用量按钮的端到端点击，原因是本地嵌套面板在浏览器控制层只获得焦点而未触发按钮事件；真实大数据查询和面板单元测试已分别覆盖后台与界面逻辑。没有其他已知偏差与遗留。

## 后续关注

合并后关注预览版用户的历史查询错误与 Agent Guard 后台进程重启信号，确认大历史目录下不再出现调用栈溢出或模型查询退出。
