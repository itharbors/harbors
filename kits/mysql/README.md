# MySQL Kit

MySQL Kit 提供面向远程 MySQL 数据库的中文工作台，包括连接管理、对象浏览、数据编辑、结构查看、全库关系图和 SQL 执行。

Kit 由六个职责独立的插件组成：`mysql-core` 独占连接池与全部数据库访问，`mysql-explorer` 管理连接和对象选择，`mysql-data`、`mysql-schema`、`mysql-relationships`、`mysql-sql` 分别提供四个可独立装载的工作区。默认布局将资源管理器固定在左侧，四个工作区使用框架原生标签组展示。

## 连接与安全

- 连接时填写主机、端口、用户和密码；database 可留空，先连接服务器并从左侧选择当前账号可访问的数据库。也可以填写 database 直接进入目标库。
- “手工连接”始终可用。密码只保留在当前服务端进程的活动连接配置中；连接成功后 Panel 立即清空密码输入框，连接快照和广播不包含密码，断开连接时清除配置。
- Core 在候选连接探测成功后才替换旧连接；失败重连不会丢失原连接。
- 选择数据库同样使用候选连接池原子切换；选择失败时继续保留原数据库和连接。
- Kit workspace 负责安装 `mysql2` 运行时依赖；六个插件中只有 `mysql-core` 导入驱动并持有连接池。

### 保存的连接

保存功能只用于单机宿主。Electron 使用显式 loopback Framework 并启用 `local` 模式；Web 默认是
`off`，必须由管理员同时显式启用本机模式和 loopback 绑定：

```bash
HARBORS_CREDENTIAL_MODE=local HARBORS_BIND_HOST=127.0.0.1 npm run dev:web -- --kit ./kits/mysql
```

`::1` 也是允许的显式 loopback。`0.0.0.0`、远程地址或省略绑定时启用 `local` 都会在监听前失败；
`multi-user` 尚未实现并直接拒绝。不要把保存功能用于远程部署、共享 Server、多用户会话或把同一
应用数据目录交给多个 Harbors 进程。

成功建立手工连接后，Panel 才会显示保存操作。保存项包含标签、host、port、user、database、TLS
选择和不透明 profile ID；这些元数据位于应用 SQLite，密码写入操作系统凭据库，不写入 SQLite、
Session、浏览器存储、URL、快照、广播或日志。保存项不会导出或显示密码，也不会在 Session 创建、
页面刷新或 Server 重启时自动连接；用户必须选择保存项并显式点击连接。

密码更新会先用完整的新密码探测候选连接，再版本化写入凭据库，最后切换连接；探测或写入失败时
保留旧连接和旧保存项。删除当前正在使用的保存项会先断开连接，再删除 OS 项和元数据。删除失败
不会伪装成成功，更新或删除也不会把旧密码恢复到 Panel。

本机模式依赖当前操作系统和用户会话可用、已解锁且允许访问的原生凭据后端。Electron 和显式
loopback Web 都通过 Server 使用同一个 Harbors 自有的 `@itharbors/native-credential-vault` Node-API
适配器；浏览器本身不接触系统凭据库或密码。适配器在 macOS ARM64 上直接调用 Security.framework，
不包含第三方 keyring、文件、shell helper、应用内固定密钥或明文存储回退。后端缺失、锁定或拒绝
访问时，Panel 会隐藏/停用保存能力并显示稳定原因，
但手工连接仍可使用；解锁凭据库或恢复系统服务后，可点击“重新检测”恢复保存项，无需重启
Harbors。重新检测只刷新能力和非秘密 profile 列表，不会自动连接或读取保存的密码；不存在
自动回退。若 OS 项被外部删除，
Harbors 不会恢复或显示原密码：回到手工模式，删除失效的保存项，重新连接并另存为新项。

当前只支持 macOS ARM64 保存凭据。Windows、Linux 和 macOS x64 会在不加载任何原生凭据后端的
情况下稳定报告“不可用”，手工连接仍可使用；这些平台必须分别完成自有目标模块、系统后端和长期
smoke 验收后才能视为已支持。无论平台如何，系统登录账号、能够读取进程内存的恶意代码、键盘
记录器、MySQL 服务端和 TLS 信任均不在该本机静态存储边界内。

## 数据与结构

- 数据页支持 25、50、100、250 条分页，并按主键稳定排序。
- 普通表可以新增；只有存在非二进制主键时才能编辑和删除。视图始终只读。
- BIGINT、DECIMAL、时间、JSON 和 BLOB 使用保留类型信息的序列化格式，避免精度损失或二进制误编辑。
- 结构页展示字段、复合主键、索引、外键和 MySQL 返回的定义 SQL。

## 全库关系图

- 关系图只展示当前 database 的普通表和真实声明的外键，不展示 view，也不根据字段名称推断关系。
- 复合外键按 constraint 聚合；自引用、循环和平行外键分别保留。
- 支持搜索、拖拽平移、滚轮与工具栏缩放、适应窗口，以及可见的非 SVG 关系明细。
- 点击或使用键盘激活节点会选择对应表并打开结构 Panel。

## SQL 工作区

- 每次显式执行一条 SQL，行结果最多显示 500 条。
- mutation 结果展示影响行数、插入 ID 和警告状态。
- SQL 错误不会清空草稿；连接变化会清理旧结果但保留当前草稿。
