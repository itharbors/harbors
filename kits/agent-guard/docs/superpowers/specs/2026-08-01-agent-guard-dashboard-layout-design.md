# Agent Guard 单窗口监控台设计

## 目标

将 Agent Guard 设计为占满 Web 宿主窗口的单窗口监控台。用户无需滚动页面即可在总览中同时看到实时路由、各 Agent 历史摘要和趋势；事件处理与管理配置通过独立 Tab 分离。

## 信息架构

顶部保留产品标题和保护状态，并提供三个符合 ARIA Tabs 语义的导航项：

- **总览**：观测路由在上，历史用量在下。
- **事件记录**：仅展示异常事件、状态和处理操作，Tab 显示非零事件数徽标。
- **设置**：集中展示预警阈值、历史采集、缓存管理和隐私说明。

默认打开总览。2 秒实时轮询与 30 秒历史轮询不得重置当前 Tab、键盘焦点、策略表单草稿、历史域或时间范围。

## 固定视口布局

`html`、`body`、根节点和工作区使用宿主提供的完整宽高。工作区采用三行网格：紧凑标题、Tab 导航、`minmax(0, 1fr)` 活动内容区。页面级 `body` 固定 `overflow: hidden`，不产生横向或纵向滚动条。

总览内容区采用上下网格，并在常规桌面窗口（高度不低于 680 px）内完整显示：

1. 观测路由使用紧凑的两个横排，分别展示 Claude 和 Codex。
2. 历史用量占据剩余高度，摘要、图表和控制器在可用空间内收缩。

事件记录或设置内容超出可用高度时，只允许活动内容区内部滚动，标题和 Tab 始终固定。高度低于 680 px 或窄屏设备无法容纳总览时，也只允许活动内容区内部滚动，不恢复页面级滚动。

宽度从 320 px 到宿主全宽均不得产生页面级横向滚动。窄屏下路由指标、Agent 历史摘要和设置卡自然换行。

## 总览：观测路由

观测路由保留 Claude、Codex 两个横排及当前端点信息。每排展示 Agent、Provider、Hostname、置信度、上行、下行、连接数和活跃任务。没有活动端点的 Agent 不伪造流量；当两个 Agent 均无端点时显示后台监控继续运行的空状态。

## 总览：历史用量

保留“网络流量 / 模型用量”和时间范围切换。界面不提供 Claude/Codex 过滤器，查询同时包含两个 Agent。

### Agent 摘要

历史摘要恢复 Agent 维度，并与观测路由保持相同的两个横排：

- 第一排 Claude。
- 第二排 Codex。

网络模式每排显示上行、下行和覆盖率。模型模式每排显示输入 Token、输出 Token、缓存 Token、请求数和会话数，并显示相应覆盖状态。某 Agent 或指标完全没有采集数据时显示“未采集 / 覆盖 0%”，不得显示为零。

后端历史响应继续保留来源维度；面板视图模型按 Agent + 指标汇总同一 Agent 的 provider/hostname 序列。摘要必须与相同 Agent、相同时间范围的趋势原始数据一致。

### 趋势图

趋势图继续按指标合并 Claude 与 Codex，避免四条以上曲线造成噪音：

- 网络模式：上行、下行两条线。
- 模型模式：输入 Token、输出 Token 两条线。

同一时间桶内累加两个 Agent 的非缺失值；全部来源缺失时保持断点，不转换为零。曲线使用真实 `point.start/end` 对齐。

图表增加可见横坐标：

- 轴标题固定为“时间（本地时区）”。
- `1h` 使用本地 `HH:mm`。
- `24h` 使用本地 `HH:mm`，跨日时首个刻度带月日。
- `7d` 和 `30d` 使用本地 `MM-DD`。
- `90d` 和 `1y` 使用本地 `YYYY-MM`。
- 至少显示起点、终点和中间刻度；刻度来自实际查询范围，不从数组索引推导。

图例继续以颜色和实线/虚线双重区分指标。图表的可访问名称包含时间范围与两项汇总值。

## 事件记录

事件记录 Tab 只展示事件列表、状态和恢复、结束、忽略操作，不再展示策略表单。无事件时明确说明后台监控仍在继续。事件操作失败以内联错误显示并保留当前 Tab、焦点和事件上下文。

## 设置

设置 Tab 集中承载所有非日常观测操作：

1. **保护策略**：警告阈值、暂停阈值和保存操作。
2. **历史采集**：本地日志回填开关及其当前状态。
3. **缓存管理**：持久化类型、当前占用、最早/最新历史时间、清空历史二次确认。
4. **隐私说明**：仅采集本机连接元数据，不采集提示词、响应内容或凭据。

总览底部不再出现本地日志回填、存储占用、清空历史或隐私说明。缓存状态缺失时显示明确的不可用状态；清空历史仍不得删除策略或事件记录。

## 渲染与状态

稳定页面外壳与轮询数据分离。重绘前后保存活动 Tab、焦点键、输入选区和表单草稿。历史查询结果绑定 `domain:range` 查询键，切换期间显示 loading，不把旧域数据画在新域控件下。

本次不修改采集器、历史存储 schema、事件判定、策略协议或 Bridge 消息。Agent 分行摘要由纯面板视图模型生成；聚合总趋势继续使用现有固定指标视图模型。

## 错误和空状态

- 实时采集不可用时显示错误和重试入口。
- 历史请求加载、失败和空数据不影响实时路由。
- Agent 或指标缺失显示“未采集”，实测零显示 `0`。
- 设置保存失败保留表单草稿和当前 Tab。
- 清空历史失败保留二次确认上下文并显示内联错误。

## 验收标准

1. 常规桌面窗口高度不低于 680 px 时，总览占满窗口且 `documentElement.scrollHeight === innerHeight`，无页面级滚动条。
2. 任何尺寸下页面级横向滚动宽度不超过视口；过矮或窄屏仅活动内容区内部滚动。
3. 顶部存在“总览 / 事件记录 / 设置”三个可键盘操作的 ARIA Tab；轮询不丢状态。
4. 总览严格按“观测路由在上、历史用量在下”排列。
5. 历史摘要固定显示 Claude、Codex 两排，并在网络/模型模式下展示各自指标和覆盖率。
6. 趋势图只显示两条聚合指标线，缺失保持断点；横轴显示本地时间刻度和“时间（本地时区）”。
7. 总览不显示日志回填、缓存占用、清空历史或隐私说明。
8. 事件 Tab 不显示策略表单；设置 Tab 包含策略、回填、缓存、清理和隐私说明。
9. Agent Guard 单元测试、面板可访问性测试和官方 `kit:check` 通过。
10. 使用 `npm run dev:web` 在 Web 宿主完成现场验收，不启动 Electron。

## 非目标

- 不调整采集器、流量识别、历史持久化格式或阈值算法。
- 不新增第三方图表库。
- 不启动 Electron，不改变桌面专属行为。
