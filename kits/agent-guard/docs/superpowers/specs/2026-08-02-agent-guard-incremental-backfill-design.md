# Agent Guard 增量回填与进度设计

## 背景

Agent Guard 已能从 Claude 与 Codex 本地 JSONL 会话日志回填模型用量，但当前体验有三个缺口：Web 预览重启后丢失内存游标、回填期间界面只显示零值且没有进度、固定的 10,000 文件发现上限可能永久漏掉较旧日志。此外，单文件最多读取 4 MiB，而“大小与修改时间未变化即跳过”的判断没有确认游标已经到达文件末尾，可能让大文件剩余内容无法继续解析。

本设计让 Web 开发预览与桌面产品都使用隔离的本地持久化缓存，以每个文件的读取游标进行增量回填，并向设置页暴露可信的进度与完整性状态。

## 已选方案

采用“持久化文件游标 + 有界批处理 + 运行时进度”方案。

没有采用单一全局时间戳，因为旧日志可能追加、截断或轮转，仅记录“上次回填时间”会漏数。没有引入 SQLite 索引，因为现有 NDJSON 历史存储、原子 JSON 游标和事件摘要去重已经足以支撑当前数据规模；新增数据库会扩大迁移、损坏恢复和发布范围。

## 范围

本次包含：

- Web 开发预览的隔离持久化历史目录。
- 桌面端现有持久化目录继续使用，不迁移或共享 Web 数据。
- 可迁移的回填检查点、按文件 offset 增量读取与解析器版本处理。
- 最近文件优先的有界批处理，不再把 10,000 当作永久截断上限。
- 后台回填进度与最近一次结果的契约、服务状态和设置页展示。
- 大文件、文件增长、截断、轮转、损坏记录、缺失目录和部分完成的测试。

本次不包含：

- 上传、同步或跨设备共享历史。
- 采集提示词、响应正文、凭据或日志原文。
- 将开发预览缓存合并进桌面正式缓存。
- 新数据库或新的图表库。

## 缓存边界

桌面端继续使用应用数据目录中的 `agent-guard`。Web 开发栈在未显式提供 `HARBORS_AGENT_GUARD_DATA_DIR` 时，使用当前 worktree 下被 Git 忽略的 `.cache/agent-guard/web`。因此重新运行 `npm run dev:web` 可以继续回填，但不同 worktree、Web 开发与桌面正式环境互不污染。

历史存储的选择规则改为：只要宿主明确提供绝对 `dataDir` 就使用文件存储；没有 `dataDir` 的普通 Web/测试宿主仍使用内存存储。清空历史会删除派生历史和回填游标，但保留“是否开启本地日志回填”的用户设置。

## 回填检查点

`history-cursors.json` 升级为带版本的检查点文档，并兼容读取当前按摘要索引的 v1 结构。每个文件只保存非敏感信息：

- 基于本机 salt 计算的文件身份摘要，不保存原始路径。
- Agent、已观察到的文件大小、修改时间和已消费 offset。
- 是否已记录该会话、解析器版本、最近成功解析时间。
- 文件是否已经完整消费。

跳过文件必须同时满足：身份未变、大小与修改时间未变、解析器版本一致，并且 `offset >= size`。文件增长时从 offset 继续；文件缩小或身份变化时从 0 重新解析；解析器版本升级时从 0 重建该文件的派生事件。事件摘要保持幂等，重复解析不会重复计数。

## 有界批处理与顺序

文件发现与文件解析分成两个阶段：

1. 递归发现所有候选 JSONL，拒绝符号链接和越界路径，并统计候选数与发现错误。
2. 根据修改时间倒序排列，把“未完成、已增长、解析器过期”的文件放在队首。
3. 每批限制处理文件数和读取字节数；达到预算时保存全部已完成游标并返回 `partial`，下一轮从未完成文件继续。
4. 单文件每次最多读取 4 MiB，但只有 offset 到达文件末尾才标记完成；未读完的大文件会在后续批次继续。
5. 启动时立即运行，部分完成时使用短间隔继续；追平后恢复每 5 分钟增量检查。

这保证最近数据先出现，同时最终遍历全部候选文件。安全上限只限制单批资源消耗，不再永久忽略第 10,001 个文件。

## 状态契约

`HistoryStatus` 增加 `backfill`：

- `state`: `disabled | idle | discovering | scanning | partial | complete | error`
- `startedAt`、`updatedAt`、`completedAt`
- `agents`: 当前 Agent 与 Claude/Codex 分项统计
- `filesDiscovered`、`filesEligible`、`filesScanned`、`filesSkipped`
- `bytesRead`、`eventsWritten`、`unsupportedRecords`、`errors`
- `remainingFiles`；发现完成前为 `null`
- `lastSuccessfulEventAt` 和不含原始路径/内容的 `message`

进度只在发现完成且 `filesEligible > 0` 时显示确定百分比：`已处理 eligible / filesEligible`。发现阶段显示不确定进度，不伪造百分比。`partial` 表示本批预算耗尽但检查点已安全保存；`error` 仅用于本轮无法继续的错误。单个损坏记录或不可读文件计入错误并允许其他文件继续。

最近一次完成摘要写入检查点，以便重启后设置页能显示“上次完成时间、写入事件数、是否完整”。运行中的瞬时字段只保存在服务内存中。

## 界面

总览继续专注观测路由和历史用量。历史标题旁只显示一个紧凑状态：`正在回填`、`历史已更新` 或 `历史不完整`。

设置页“历史采集”区域展示：

- 开关及 Web/桌面的实际缓存位置类别，不展示完整本地路径。
- 发现阶段的不确定进度，或扫描阶段的进度条与 `已处理 / 待处理`。
- Claude、Codex 各自的文件数、写入事件数和错误数。
- 上次完成时间、最近成功事件时间、当前结果是完整还是部分。
- `立即继续回填` 操作；运行中禁用，关闭回填时隐藏。

缓存管理继续显示占用、最早/最新历史和清空历史。清空后进度、派生数据和游标一起归零；重新开启或点击继续会从本地日志重新构建。

## 数据流与并发

服务持有唯一回填协调器，`start`、定时器、设置更新和手动继续都调用同一个 `requestRun()`。若已有运行，不并发启动第二次，而是合并一次“完成后再检查”请求。进度更新采用单调 `runId`，旧运行不得覆盖新状态。

面板继续轮询 `getHistoryStatus`，无需新增推送通道。回填状态更新不改变历史 generation；只有追加了新事件或清空历史时才改变可查询数据。面板在轮询重绘时继续保留页签、焦点、表单草稿和确认状态。

## 错误与隐私

- 缺失的 Claude/Codex 日志目录记为该 Agent 的可解释状态，不阻止另一 Agent。
- 文件级错误只返回计数和稳定错误码，不返回路径、日志内容或异常中可能包含的敏感文本。
- 检查点、进度和测试夹具不得保存提示词、响应、凭据、Authorization 或原始文件名。
- 持久化写入继续使用原子替换和 `0600` 权限；检查点损坏时保留历史数据，重建游标并依靠事件摘要去重。

## 验收标准

- Web 预览重启后读取隔离缓存，未变化文件不会重新解析。
- 桌面端继续从既有数据目录增量回填，不读取 Web 开发缓存。
- 19,379 个候选文件不会因 10,000 单批预算而永久遗漏；多轮后 `remainingFiles` 归零。
- 超过 4 MiB 的未变化文件会跨批次读到 EOF。
- 增长、截断、轮转和解析器升级均不会漏数或重复计数。
- 设置页能区分发现、扫描、部分、完成、失败，并显示 Claude/Codex 分项进度。
- 总览只显示紧凑状态，不放置缓存管理操作。
- 完整 Agent Guard 测试、Kit 检查和 Web 浏览器验收通过；不启动 Electron。
